# AI 猜拳挑战赛

可运行的蓝色科技风石头剪刀布游戏，使用 **React 19、TypeScript、Vite 8、Tailwind CSS 4**。无需后端、API 密钥或在线 AI 服务。

## 一键快速启动（推荐）

### Windows：双击启动

1. 首次使用先安装 [Node.js 24 LTS](https://nodejs.org/)（最低版本 22.13，安装时保留 npm）。
2. 完整下载并解压本项目，或克隆仓库。
3. 双击项目根目录的 **`start.bat`**。

脚本会自动定位项目目录、检查 Node.js、按需安装依赖，然后启动游戏并打开默认浏览器。无需手动输入安装命令或提前构建。

- 游戏地址固定为 **http://127.0.0.1:5173**。
- 缺少依赖、已安装的直接依赖与锁文件不匹配，或上次一键启动后依赖配置发生变化时，自动执行 `npm ci --include=dev --include=optional`；依赖就绪时跳过安装。
- 首次安装需要联网；依赖就绪后，游戏可在本地离线运行。
- 游戏运行期间请保留终端窗口；按 **Ctrl+C** 停止服务。
- 浏览器未自动打开时，可手动访问上面的地址。
- 启动失败时会显示错误，Windows 窗口会等待按键，方便查看原因。

### 命令行快速启动（Windows / macOS / Linux）

在项目根目录执行，依赖缺失时也会自动安装：

```bash
node scripts/start.mjs
```

已安装 npm 时，也可使用：

```bash
npm run quickstart
```

仅启动服务、不自动打开浏览器：

```bash
npm run quickstart -- --no-open
```

### 常见问题

- **找不到 Node.js / 版本过低**：安装 Node.js 24 LTS 后，重新双击 `start.bat`。
- **找不到 npm**：重新运行 Node.js 安装程序，确保安装 npm。脚本兼容本开发环境的临时 npm，但普通使用者不需要 `.tools` 目录。
- **依赖安装失败**：检查网络与错误输出后重新启动；也可在项目目录手动执行 `npm ci`。脚本不会自动切换 npm 镜像源。
- **5173 端口已占用**：如果已有游戏窗口，直接打开游戏地址即可；否则停止占用该端口的程序后再启动。脚本不会结束其他进程或自动切换端口，避免本地战绩因网站来源变化而看似丢失。
- **不要直接双击 `index.html`**：请通过启动脚本或下面的开发命令访问游戏。

## 手动安装与开发

建议 Node.js 24 LTS（最低 22.13）和 npm。在项目目录执行：

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。生产构建与预览：

```bash
npm run build
npm start
```

构建结果位于 `dist/`，可部署到静态网站服务。请通过 HTTP/HTTPS 访问，不要直接双击 HTML 文件。

核心规则测试：

```bash
npm test
```

`npm start` 用于预览已经构建好的 `dist/`；日常游玩推荐一键启动，开发时可用 `npm run dev`。

## 游戏玩法

1. 选择简单/困难模式，以及三局两胜、五局三胜或七局四胜。
2. 点击“开始游戏”，AI 先选定并锁定本回合出拳。
3. 玩家出拳，播放揭晓动画后同时公布双方手势和结果。
4. 点击“下一局”继续；率先获得 2、3、4 分的一方赢得比赛。
5. 平局完整记录，但双方均不加分；因此实际回合数可以超过赛制名称中的局数。
6. 结果页面支持当前配置重赛或返回主菜单；历史战绩支持展开每回合详情。

## 摄像头手势识别

在竞技场点击 **开启摄像头** 并授权后，即可看到镜像预览、手部关键点、识别手势和置信度：

- **石头**：握紧拳头，拇指收拢。
- **剪刀**：伸出食指和中指，形成朝向镜头的 V 字。
- **布**：五指张开，掌心朝向镜头。

请保持一只手完整入镜、光线充足，避免逆光。手势连续稳定约 0.6 秒后，点击 **使用「石头 / 剪刀 / 布」出拳** 提交；仅识别不会自动出拳。原有三种出拳按钮始终保留。

开始比赛之前可练习识别；正式比赛只有等待出拳阶段允许提交。下一局会清除上一局的识别确认，AI 仍然先锁定出拳，不读取实时摄像头结果。无手、多手、低置信度、其他手势以及过期画面均不能提交。

点击 **关闭摄像头** 会停止设备和识别线程。离开页面、切换到后台、返回主菜单或比赛结束时自动关闭；刷新后需要重新手动开启。摄像头只请求视频权限，不使用麦克风，画面不录制、不上传、不写入历史记录。

识别使用 [MediaPipe Gesture Recognizer](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer/web_js)。模型和运行资源从本项目提供；安装依赖后可离线运行，无需 API 密钥。识别在独立 Web Worker 中执行，避免阻塞游戏动画。默认接受置信度至少 75% 的结果，并做连续帧稳定性检查。

**浏览器要求与故障处理：**

- 使用支持摄像头、WebAssembly、Web Worker 和 OffscreenCanvas 的现代浏览器（建议新版 Chrome / Edge）。
- 本机通过 `http://127.0.0.1:5173` 或 `http://localhost:5173` 访问；远程访问需要 HTTPS。普通局域网 HTTP 地址无法申请摄像头权限。
- 权限被拒绝时，在地址栏网站权限中允许摄像头，再点击“重试摄像头”；设备被占用时先关闭其他相机应用。
- 嵌入页面可能限制摄像头授权，遇到权限问题请在独立浏览器标签页打开游戏地址。
- 模型加载失败时确认 `public/vision/gesture_recognizer.task` 存在，并重新运行一键启动脚本。请完整下载仓库中的模型文件。
- 识别准确度受光线、遮挡、拍摄角度与设备性能影响，可调整手势后重试或使用原有按钮。

## AI 策略与公平性

- **简单模式**：使用 `crypto.getRandomValues` 和拒绝采样消除取模偏差，每次独立等概率选择手势，不读取历史。
- **困难模式**：前三回合随机。此后分析本场最近 18 个已完成回合：近期出拳频率权重更高，与上一手匹配的历史出拳转换额外加权。预测最可能的下一手并选择克制手势；并列预测随机择一，另保留 22% 随机探索概率。
- AI 仅在 `startMatch` 和 `nextRound` 中生成。`submitMove` 只记录玩家手势、切换到揭晓阶段，绝不生成或修改 AI 手势。算法没有玩家本回合选择参数。
- 这是本地休闲游戏；AI 算法不作弊，但客户端代码与本地存储可由用户自行查看或编辑，不属于防篡改竞技服务。

## 状态、计分与恢复

`主菜单 → waiting（AI 已锁定）→ revealing（按钮锁定）→ result / finished`。

只有 `waiting` 允许出拳；只有 `revealing` 允许结算；只有 `result` 允许下一局。同步状态引用与纯状态转换双重防止快速点击重复提交、重复计分。达到目标后立即结束。动画计时器在卸载时清理。

进行中比赛每次变更写入本地存储。刷新后恢复同一份已锁定的 AI 手势；若刷新发生在动画期间，会继续结算该回合一次。返回主菜单需要确认，并放弃未完成比赛，不计入历史。

## 战绩存储

- `localStorage["rps.history.v1"]`：完成的比赛数组，包含唯一 ID、时间、难度、目标分、比分及每回合详情。按比赛 ID 去重，统计由历史数组即时计算。
- `localStorage["rps.active.v1"]`：当前比赛快照，包括本回合已锁定的 AI 手势。
- 读取时校验结构，并重算逐局结果及累计分数；异常数据或存储失败会显示提示，不静默声称保存成功。
- 清空战绩弹出二次确认；取消不删除数据，确认只清除历史及相应统计，进行中比赛不变。清空时若已处于最终结果页，则同时移除该已完成快照，防止刷新后重新入库。
- 数据仅属于当前浏览器与网站来源，不跨设备同步。无痕窗口、浏览器清理、存储权限或容量限制可能影响持久化。

界面支持键盘焦点、原生模态对话框、结果朗读区域以及系统减少动态效果设置。支持 WebMCP 的浏览器可读取公开比赛状态并通过同一状态校验提交手势；尚未揭晓的 AI 手势不通过该接口公开。当前验证浏览器未提供原生 WebMCP，故该可选接口未进行原生环境验证，不影响按钮交互。
