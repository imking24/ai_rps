# AI 猜拳挑战赛

可运行的蓝色科技风石头剪刀布游戏，使用 **React 19、TypeScript、Vite 8、Tailwind CSS 4**。无需后端、API 密钥或在线 AI 服务。

## 安装与启动

建议 Node.js 24 LTS（最低 22.13）和 npm。在项目目录执行：

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。生产构建与预览：

```bash
npm run build
npm start
```

构建结果位于 `dist/`，可部署到静态网站服务。请通过 HTTP/HTTPS 访问，不要直接双击 HTML 文件。

核心规则测试：

```bash
npm test
```

本开发环境仅内置 Node.js，已在 `.tools/package/` 临时安装 npm；因此也可执行 `node .tools/package/bin/npm-cli.js run dev`。其他电脑按标准方式安装 Node.js/npm 即可，不需要该临时目录。

## 游戏玩法

1. 选择简单/困难模式，以及三局两胜、五局三胜或七局四胜。
2. 点击“开始游戏”，AI 先选定并锁定本回合出拳。
3. 玩家出拳，播放揭晓动画后同时公布双方手势和结果。
4. 点击“下一局”继续；率先获得 2、3、4 分的一方赢得比赛。
5. 平局完整记录，但双方均不加分；因此实际回合数可以超过赛制名称中的局数。
6. 结果页面支持当前配置重赛或返回主菜单；历史战绩支持展开每回合详情。

## AI 策略与公平性

- **简单模式**：使用 `crypto.getRandomValues` 和拒绝采样消除取模偏差，每次独立等概率选择手势，不读取历史。
- **困难模式**：前三回合随机。此后分析本场最近 18 个已完成回合：近期出拳频率权重更高，与上一手匹配的历史出拳转换额外加权。预测最可能的下一手并选择克制手势；并列预测随机择一，另保留 22% 随机探索概率。
- AI 仅在 `startMatch` 和 `nextRound` 中生成。`submitMove` 只记录玩家手势、切换到揭晓阶段，绝不生成或修改 AI 手势。算法没有玩家本回合选择参数。
- 这是本地休闲游戏；AI 算法不作弊，但客户端代码与本地存储可由用户自行查看或编辑，不属于防篡改竞技服务。

## 状态、计分与恢复

`主菜单 → waiting（AI 已锁定）→ revealing（按钮锁定）→ result / finished`。

只有 `waiting` 允许出拳；只有 `revealing` 允许结算；只有 `result` 允许下一局。同步状态引用与纯状态转换双重防止快速点击重复提交、重复计分。达到目标后立即结束。动画计时器在卸载时清理。

进行中比赛每次变更写入本地存储。刷新后恢复同一份已锁定的 AI 手势；若刷新发生在动画期间，会继续结算该回合一次。返回主菜单需要确认，并放弃未完成比赛，不计入历史。

## 战绩存储

- `localStorage["rps.history.v1"]`：完成的比赛数组，包含唯一 ID、时间、难度、目标分、比分及每回合详情。按比赛 ID 去重，统计由历史数组即时计算。
- `localStorage["rps.active.v1"]`：当前比赛快照，包括本回合已锁定的 AI 手势。
- 读取时校验结构，并重算逐局结果及累计分数；异常数据或存储失败会显示提示，不静默声称保存成功。
- 清空战绩弹出二次确认；取消不删除数据，确认只清除历史及相应统计，进行中比赛不变。清空时若已处于最终结果页，则同时移除该已完成快照，防止刷新后重新入库。
- 数据仅属于当前浏览器与网站来源，不跨设备同步。无痕窗口、浏览器清理、存储权限或容量限制可能影响持久化。

界面支持键盘焦点、原生模态对话框、结果朗读区域以及系统减少动态效果设置。支持 WebMCP 的浏览器可读取公开比赛状态并通过同一状态校验提交手势；尚未揭晓的 AI 手势不通过该接口公开。当前验证浏览器未提供原生 WebMCP，故该可选接口未进行原生环境验证，不影响按钮交互。
